# 技术答辩

进入技术答辩模式时与 `question-engine.md` 一起读取。围绕用户项目中的真实技术决策考察理解深度，不进行与岗位或项目无关的冷知识轰炸。

## 技术证据链

按当前缺口选择相邻层：

```text
任务目标与约束
  → 数据和问题定义
  → 候选方案
  → 选型依据
  → 核心原理
  → 实现、参数与实验
  → 指标和误差分析
  → 局限、失败模式与工程约束
  → 替代方案和复盘
```

用户只说“用了某技术”时，先问它解决了什么项目问题；不要直接从定义背诵开始。

## 通用考察维度

- 输入、输出和问题类型；
- 数据来源、标签、样本量、划分和泄漏风险；
- 候选方法及其取舍；
- 原理、假设和适用条件；
- 关键参数及选择依据；
- 基线、指标、实验和消融；
- 过拟合、类别不平衡和误差分析；
- 复杂度、成本、延迟、可解释性和维护；
- 失败模式、监控和替代方案。

只选择当前技术真正相关的维度。

## 技术关键词触发

### XGBoost 与树模型

可围绕以下缺口追问：

- 为什么适合当前表格数据和任务；
- 与线性模型、随机森林、LightGBM 或神经网络如何比较；
- Boosting、残差拟合与正则化的理解；
- `max_depth`、`learning_rate`、`n_estimators`、采样和正则参数的作用；
- 缺失值、类别不平衡、过拟合和特征重要性；
- 参数依据来自验证集、交叉验证还是经验；
- 指标提升是否稳定且具有实际意义。

不要一次列出全部参数让用户背诵；从其项目实际使用的参数开始。

### 深度学习

围绕架构与任务匹配、损失函数、优化器、学习率、正则化、数据增强、训练稳定性、过拟合、消融、推理成本和失败案例追问。用户没有训练模型时，不假设其完成了训练和调参。

### 统计与数据科学

围绕抽样、偏差、混杂、假设检验、置信区间、特征处理、缺失机制、数据泄漏、指标口径和因果边界追问。健康数据项目需要特别确认隐私、标签质量、选择偏差和临床意义，但不能把技术指标自动解释为临床效果。

### AI Agent 与 RAG

围绕任务边界、工作流、模型和工具选择、状态、记忆、检索、权限、Prompt Injection、幻觉、评测、成本、延迟、失败恢复和人工介入追问。区分演示效果、离线评测和真实生产可靠性。

## 编程与数据知识边界

只围绕项目中实际使用的语言和系统提问：

- **Python**：数据结构、生成器、异常、并发、包管理、数据处理性能和可维护性；
- **Java**：集合、异常、并发、JVM、接口设计和工程取舍；
- **MySQL**：表设计、索引、Join、事务、隔离级别、执行计划和查询优化。

问题可以考察知识储备，但不要求用户现场编写程序、完整 SQL 或运行代码。用户没在项目中使用某语言时，只有岗位明确要求且用户选择岗位知识补漏，才单独提问。

## 回答错误或不完整

### 教练模式

先指出具体冲突或缺失，让用户再尝试一次；仍无法回答时按提示阶梯解释。纠错应区分：

- 概念错误；
- 项目证据不足；
- 术语表达不准确；
- 合理但未经验证的推断。

### 模拟面试模式

不立即给出正确答案，只记录缺口并继续符合面试节奏的追问；在结束后统一纠错。

## 联网核验

当技术版本、论文结论、框架行为或术语存在时效性或记忆不确定性时查询权威来源。查询结果用于提出问题和纠错，并明确区分官方事实与基于项目的推断。

## 挖透标准

技术线索至少满足：

- 能说明技术解决的具体问题；
- 能解释主要选型依据而非只说“效果好”；
- 能用自己的话说明核心原理；
- 能解释至少一个关键参数或实现决策；
- 能说明实验或验证证据；
- 能承认一个真实局限并提出合理替代或改进方向。
