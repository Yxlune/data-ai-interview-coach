# 技术答辩

进入技术答辩模式时与 `question-engine.md` 一起读取。围绕用户项目中的真实技术决策考察理解深度，不进行与岗位或项目无关的冷知识轰炸。

## 技术证据链

按当前缺口选择相邻层：

```text
任务目标与约束
  → 数据和问题定义
  → 候选方案
  → 选型依据
  → 核心原理
  → 实现、参数与实验
  → 指标和误差分析
  → 局限、失败模式与工程约束
  → 替代方案和复盘
```

用户只说“用了某技术”时，先问它解决了什么项目问题；不要直接从定义背诵开始。

## 通用考察维度

- 输入、输出和问题类型；
- 数据来源、标签、样本量、划分和泄漏风险；
- 候选方法及其取舍；
- 原理、假设和适用条件；
- 关键参数及选择依据；
- 基线、指标、实验和消融；
- 过拟合、类别不平衡和误差分析；
- 复杂度、成本、延迟、可解释性和维护；
- 失败模式、监控和替代方案。

只选择当前技术真正相关的维度。

## 岗位与技术知识

进入技术答辩后读取 [岗位与技术知识路由](knowledge-routing.md)，根据 JD、当前项目和技术栈图谱选择一个主岗位知识包：

- [数据科学岗位知识](data-science-knowledge.md)；
- [机器学习与 AI 算法岗位知识](ml-ai-algorithm-knowledge.md)；
- [AI Agent 岗位知识](ai-agent-knowledge.md)。

跨域项目最多再加载一个辅知识包。只有项目或 JD 触发 Python、Java 或 MySQL 时才读取 [Python、Java 与 MySQL 项目知识](programming-and-sql-knowledge.md)。不要同时加载所有知识文件。

知识包只提供追问维度。下一问必须关联用户刚刚说过的项目事实，并沿用途、选型、原理、实现、验证或边界中的当前缺口推进。框架名和论文不能证明用户实施过相应工作。

问题可以考察知识储备，但不要求用户现场编写程序、完整 SQL 或运行代码。用户没在项目中使用某语言时，只有岗位明确要求且用户选择岗位知识补漏，才单独提问。

## 回答错误或不完整

### 教练模式

先指出具体冲突或缺失，让用户再尝试一次；仍无法回答时按提示阶梯解释。纠错应区分：

- 概念错误；
- 项目证据不足；
- 术语表达不准确；
- 合理但未经验证的推断。

### 模拟面试模式

不立即给出正确答案，只记录缺口并继续符合面试节奏的追问；在结束后统一纠错。

## 联网核验

当技术版本、论文结论、框架行为或术语存在时效性或记忆不确定性时查询权威来源。查询结果用于提出问题和纠错，并明确区分官方事实与基于项目的推断。

## 挖透标准

技术线索至少满足：

- 能说明技术解决的具体问题；
- 能解释主要选型依据而非只说“效果好”；
- 能用自己的话说明核心原理；
- 能解释至少一个关键参数或实现决策；
- 能说明实验或验证证据；
- 能承认一个真实局限并提出合理替代或改进方向。
