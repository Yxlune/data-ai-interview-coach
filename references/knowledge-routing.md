# 岗位与技术知识路由

## 目的

把 JD、简历声明和用户回答中的关键词映射到最小知识包，为动态追问引擎提供考察维度。知识包是追问锚点，不是固定题库；下一问仍由当前项目缺口决定。

## 路由顺序

1. 从 JD 提取岗位任务、必备能力、加分项、语言和框架，不把公司宣传语当作能力要求。
2. 从当前项目提取问题类型、数据、算法、框架、系统、个人决策和结果声明。
3. 选择一个主岗位族；确有跨域任务时最多增加一个辅岗位族。
4. 进入技术答辩时加载 `technical-defense.md`、本文件和主岗位族知识包。
5. 只有项目或 JD 明确触发 Python、Java 或 MySQL 时，才额外加载 `programming-and-sql-knowledge.md`。
6. 发现版本、论文结论、框架行为或新术语需要核实时，按 `security-and-research.md` 联网，不把整份知识包重新搜索一遍。

## 岗位族

### 数据科学

适用于数据科学、数据分析、产品分析、统计建模、健康数据科学，以及以数据洞察、实验、预测或决策支持为核心的岗位。读取 [数据科学知识](data-science-knowledge.md)。

### 机器学习与 AI 算法

适用于机器学习算法、AI 算法、模式识别、预测、排序、推荐、NLP、计算机视觉及深度学习岗位。读取 [机器学习与 AI 算法知识](ml-ai-algorithm-knowledge.md)。

### AI Agent 开发

适用于 Agent、RAG、LLM 应用、工具调用、工作流编排、知识库问答和智能助手岗位。读取 [AI Agent 知识](ai-agent-knowledge.md)。

“数据开发”不是 V1 主岗位族。若 JD 只涉及批处理、数据仓库或流式平台，说明当前覆盖有限；若它只是数据科学项目中的数据管道，则围绕数据质量、可复现性、调度和上下游契约追问，不扩展为完整数据开发面试。

## 混合岗位

- 数据科学 + 算法：主线按最终交付决定。洞察、实验与业务决策为主选数据科学；模型性能与算法研发为主选算法。
- 算法 + Agent：底层模型训练或微调为主选算法；工作流、RAG、工具和评测为主选 Agent。
- 数据科学 + Agent：数据问答或分析助手为主选 Agent，并从数据科学包加载指标口径、数据质量或实验相关的一个局部主题。

不要因为 JD 罗列很多框架就同时加载全部知识包。先问“这个岗位入职后最核心的交付是什么”，再决定主线。

## 关键词标准化

每个技术节点记录原词、标准名、项目用途和版本。例如：

```yaml
raw_keyword: "xgb"
canonical_name: "XGBoost"
role_route: "ml-ai-algorithm"
project_purpose: "表格数据二分类"
version: "待确认"
evidence: []
knowledge_gaps: []
research_status: "not_needed|cached|needs_check|verified"
```

只在语义明确时合并同义词。`Agent`、`workflow`、`RAG` 和 `chatbot` 不能自动视为同一概念；`准确率` 也不能自动等同于模型的 `accuracy` 指标。

## 深度层级

沿同一关键词逐级推进，但每轮只问一层：

1. **用途**：它解决项目中的什么问题，输入和输出是什么；
2. **选型**：比较过哪些方案，约束和取舍是什么；
3. **原理**：能否用自己的话说明核心机制和适用假设；
4. **实现**：关键参数、数据流程、接口或工程决策如何确定；
5. **验证**：基线、指标、实验、误差分析或评测证据是什么；
6. **边界**：失败模式、成本、局限、替代方案和复盘是什么。

校招面试不要求每个关键词都到第六层。简历核心技术、JD 高频要求和影响结果的决策需要深挖；辅助库、未实际使用的框架和岗位加分项可以停在概念与适用场景。

## 问题生成

问题必须同时关联：

- 用户刚刚提到的项目事实；
- 当前声明尚缺的一层；
- 目标岗位会关心的能力；
- 一个可回答的主问题。

例如用户说“用 XGBoost 后 AUC 提升了”，若尚未说明数据划分，优先问提升是否来自独立验证集；不要直接跳到 `max_depth` 定义。若验证可信但参数依据缺失，再追问其实际使用的一个关键参数。

## 知识纠错

区分四种情况：

- **概念错误**：与稳定原理冲突，指出冲突并让用户重答；
- **版本差异**：先确认版本和时间点，再查官方资料；
- **项目取舍**：方案不常见但可能受约束影响，先问依据；
- **证据缺失**：理论上可行不代表项目实际实现，回到实验或材料证据。

纠错只解释当前问题所需的最小知识。教学模式可以在用户二次尝试后补充；模拟面试模式留到复盘。

## 联网触发

以下内容通常需要核验：

- 框架当前 API、默认参数、弃用状态和版本差异；
- 新模型、新论文、新行业术语和公司自定义概念；
- 用户给出精确数值、性能结论或“官方推荐”说法；
- Skill 对记忆中的技术事实没有足够把握。

稳定的数学直觉、项目事实追问和通用工程取舍不必每轮联网。技术查询优先官方文档、标准和原始论文；搜索摘要不能代替打开的来源。

## 结束条件

知识线索在用途、核心原理、一个真实实现决策、验证证据和一个局限均清楚后可以关闭。用户能背定义但无法连接项目，或只有项目结果却解释不了关键技术，均不能标为“可应对追问”。
