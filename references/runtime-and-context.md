# 运行与上下文管理

## 单模型策略

V1 使用宿主平台当前选择的单一模型，不写死模型 ID，不递归调用模型，也不依赖多 Agent。能力不足时说明限制并缩小任务。

## 四层上下文

1. **常驻状态**：目标岗位、候选人概要、项目清单、关键事实、当前模式和待确认事项。
2. **当前项目**：项目背景、贡献、技术栈、指标、已回答问题和当前追问链。
3. **按需证据**：简历原句、论文章节、代码片段、实验表和历史回答；需要时才读取。
4. **外部研究**：来源、最小结论及其与当前问题的关系；避免保存整页内容。

## 长材料

先建立目录和索引，再加载与当前简历声明有关的段落。生成摘要后，只有存在冲突或证据不足才回看原文。重复文件按内容或可判断的元数据去重。

## 检查点

在项目完成、模式或项目切换、工具调用密集、长对话、用户暂停和最终输出前创建检查点。检查点保留事实、推断、证据、开放问题和下一行动。

## 额度友好策略

- 默认完整深挖 2–3 个核心项目，其余只建浅层项目卡。
- 不重复扫描、搜索或重写已经确认的内容。
- 用户额度有限时切换到精简深挖，优先处理高风险声明。
- 一次完整准备允许拆分为多次会话；每次从状态文件恢复。
- Skill 不能读取账号剩余额度，用户界面是额度状态的依据。
