# 运行、模型与上下文管理

## 适用时机

出现多份材料、多个项目、长对话、频繁联网、额度担忧或恢复旧会话时读取本文件。普通单项目追问只保留 `SKILL.md` 中的核心约束，不为预防极端情况加载全部历史。

## 宿主模型策略

V1 使用宿主平台当前选择的单一模型，不写死模型 ID，不递归调用模型，也不依赖多 Agent。Skill 不声称知道当前模型、上下文窗口或账号剩余额度；只有宿主界面或用户提供的信息可以作为依据。

根据任务调整工作强度，而不是切换到假定存在的模型：

- **交互追问**：优先短上下文、短输出和低延迟，只处理当前回答与当前线索；
- **材料建档**：分块提取事实和索引，不在一轮中同时深挖；
- **阶段诊断**：读取当前项目检查点和关键证据，进行一次集中综合；
- **最终文档**：按项目逐段生成，再做跨项目去重和一致性检查。

能力不足、文件不可读或上下文无法继续时，说明具体限制，缩小当前任务并生成检查点。不要通过重复调用、重复搜索或无边界重试弥补能力缺失。

## 上下文四层

1. **常驻状态**：目标岗位、候选人概要、项目清单、当前项目、当前模式、已确认关键事实、开放问题和下一行动。
2. **当前项目包**：背景、个人贡献、技术栈、指标、已回答问题、当前追问链和本轮所需证据。
3. **按需证据**：简历原句、论文章节、代码片段、实验表和历史回答；只有当前问题需要时才读取。
4. **外部研究**：来源、查询日期、最小结论、可信度及其与当前问题的关系；不保留整页正文。

常驻状态只保存决策所需信息。详细原文留在材料索引中，以引用位置或材料 ID 回指，避免摘要和原文同时长期驻留。

## 材料摄入

1. 先记录文件名、类型、大小或页数、相关项目、优先级和敏感性。
2. 简历与目标 JD 优先全局建索引；论文、代码和项目文档只加载与当前声明相关的部分。
3. 同一材料根据可用哈希、文件名与大小或内容摘要去重。无法确定是否重复时标为“疑似重复”，不要再次完整解析。
4. 首次读取后生成可追溯摘要，记录页码、章节、行号或表格名。只有冲突、证据不足或用户要求核对原文时回读。
5. 大段代码只提取与面试声明相关的模块、接口和决策，不把整个仓库放入对话上下文。

## 上下文压力信号

不使用固定 Token 阈值。出现下列任一信号时，将 `context_pressure` 提升为 `elevated`：

- 同一事实开始被重复询问、重复总结或重复搜索；
- 当前项目以外的细节明显干扰下一问；
- 用户一次提供多份长材料或频繁切换项目；
- 工具或宿主提示上下文、长度、配额或文件限制；
- 继续回答前需要重新阅读大量早期对话。

若已无法可靠保持事实、证据与开放问题的对应关系，则标为 `critical`。此时停止新增深挖，先生成检查点并建议在新会话恢复；不能把上下文耗尽误报为项目已完成。

## 压缩与检查点

在项目完成、项目或模式切换、工具调用密集、用户暂停、压力升高和最终输出前，按照 [检查点与跨会话恢复](recovery-and-checkpoints.md)创建精简或完整检查点。按以下优先级压缩：

1. 删除寒暄、重复问题、失败搜索和已被新结论替代的草稿；
2. 将多轮回答合并为带证据来源的事实和仍未解决的问题；
3. 保留冲突、风险、用户原话中的关键措辞和下一行动；
4. 只在恢复所必需时保留外部研究结论，不复制网页正文；
5. 用状态文件恢复时重新加载当前项目包，不重新解析所有材料。

平台若提供原生压缩或会话延续能力，可以使用，但 Markdown 检查点仍是跨平台、可审阅的恢复基线。检查点必须包含唯一可执行的 `next_action`，不能只写“继续准备”。

## 完整与精简模式

### 完整深挖

用于用户希望系统准备且上下文充足时。默认完整深挖最相关的 2–3 个核心项目，其余建立浅层项目卡。每个项目完成后立即形成检查点，不等所有项目结束。

### 精简深挖

用于用户额度有限、时间紧、材料过长或上下文压力升高时。按以下顺序处理：

1. 简历上最醒目但证据最薄弱的声明；
2. 与目标岗位最相关的技术选型和个人贡献；
3. 指标、基线、归因和落地结果；
4. 高频行为问题与明显知识缺口。

精简模式减少覆盖范围，不降低事实和安全标准。未处理内容进入开放问题，不得用泛化总结冒充完成。

## 额度沟通

- Skill 不能读取、推断或承诺用户的剩余额度，也不保证某种会员套餐足够完成一次深挖。
- 用户询问额度时，说明消耗受材料长度、项目数量、联网次数、模型和平台规则影响，并以宿主界面显示为准。
- 给出可控选择：单项目试跑、精简深挖、分会话完成或先建档后选择重点。
- 不为“节省额度”跳过安全检查、事实核验或恢复检查点；优先减少重复内容、非核心项目和不必要的联网。

## 失败与重试

读取、搜索或写入失败后先判断失败类型，再进行一次有理由的调整重试。仍失败时记录阻塞、已完成工作和替代方案并继续可安全完成的部分；禁止无界重试。
