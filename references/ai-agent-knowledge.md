# AI Agent 岗位知识

## 使用边界

本文件用于 Agent、RAG、LLM 应用、工具调用、工作流编排、知识库问答和智能助手项目。框架变化快；通用架构用于追问，具体 API、默认行为和产品能力必须按项目版本查询官方资料。

## 先确认是否真的是 Agent

不要接受标签，先确认系统是否具备：

- 明确目标和环境输入；
- 模型根据状态作出下一步决策；
- 一个或多个工具、检索或外部动作；
- 多步执行、停止条件和失败处理；
- 可观察的任务结果。

固定顺序调用一次模型可能更接近工作流；仅检索后生成可能是 RAG；只做多轮对话可能是 Chatbot。名称不同不代表项目价值低，但候选人必须准确描述自主决策边界。

## 系统架构

沿真实请求路径追问：

```text
用户目标
  → 输入与上下文
  → 路由或规划
  → 模型决策
  → 工具或检索
  → 状态更新
  → 验证与停止
  → 最终结果
```

要求用户说明每个组件的责任、输入输出、错误传播和自己负责的部分。展示架构图不等于解释了运行时行为。

## 模型与 Prompt

- 模型选择依据是能力、延迟、成本、上下文、结构化输出和工具可靠性中的哪些；
- 系统指令、用户输入、工具结果和检索文本如何分层；
- 输出是否有 Schema、解析、验证和重试；
- Prompt 修改如何通过代表性用例或回归评测验证；
- 温度、推理设置或上下文策略是否真实配置，版本是否需要核对。

不要把“Prompt 调得很好”当作证据，追问失败样例和修改前后的可复现对比。

## 工具调用

- 为什么需要该工具，模型何时可以或必须调用；
- 工具描述和参数 Schema 是否足够明确；
- 参数如何校验，返回值和错误如何处理；
- 超时、重试、限流、幂等和重复副作用；
- 读写权限、审批、最小权限和审计；
- 工具结果是否可能包含提示注入或敏感数据。

能成功调用一次 API 不是可靠性证明。至少追问一个失败路径，以及系统如何避免循环或重复执行。

## 状态、记忆与编排

- 会话状态、任务状态、用户偏好和长期记忆是否区分；
- 什么信息可以保存、何时过期、如何删除和防止跨用户污染；
- 编排是确定性工作流、模型路由、规划执行、反思重试还是多 Agent；
- 为什么需要模型决策，哪些步骤应保持确定性；
- 最大步数、时间或成本预算和停止条件；
- 中断、恢复、人工介入和补偿操作。

用户说“用了多 Agent”时，追问角色拆分是否真的降低复杂度，以及通信、冲突、重复工作和额外成本如何控制。

## RAG

按链路选择当前最薄弱的一环：

- 文档来源、解析、清洗、权限和更新；
- Chunk 的语义边界、长度、重叠和元数据；
- Embedding 选择、领域适配、版本和维度；
- 向量、关键词或混合检索；
- 查询改写、过滤、Top-K 和重排序；
- 上下文组装、引用、冲突和超长处理；
- 检索失败与生成幻觉如何区分。

评测至少区分：

- **检索层**：目标证据是否被召回、排序和过滤正确；
- **回答层**：答案是否正确、相关、忠于证据并带有可核验引用；
- **端到端**：用户任务是否完成，延迟和成本是否可接受。

“接入向量数据库”不是 RAG 选型依据。追问语料规模、更新频率、权限、召回失败和基线。

## 安全与权限

- 用户输入、网页、文件和工具结果都可能包含 Prompt Injection；
- 敏感数据是否进入模型、日志、向量库或第三方工具；
- 工具权限是否按用户、任务和动作收缩；
- 高风险写操作是否需要确认或人工审批；
- 输出是否经过内容、事实、Schema 或业务规则检查；
- 日志和 Trace 是否避免保存密钥及不必要个人数据。

安全不能只回答“加了 Guardrail”。要求说明威胁、控制点、绕过方式、剩余风险和测试证据。

## 评测与可观测性

先定义成功任务，再选择指标：

- 端到端任务完成率和人工接管率；
- 工具选择、参数和调用结果是否正确；
- RAG 召回、忠实度、引用与事实正确性；
- 轨迹中的路由、重试、循环、越权和安全违规；
- 延迟、Token 或调用成本、错误率和可用性；
- 代表性数据集、困难样例、对抗样例和回归集。

单个主观 Demo 不能证明可靠。开发期可以从 Trace 定位错误；行为稳定后需要可重复的数据集和回归评测。LLM-as-a-judge 若被使用，要追问评分标准、校准、偏差和人工抽检。

## 生产失败模式

- 模型幻觉或输出格式漂移；
- 检索缺失、过期、权限越界或证据冲突；
- 工具超时、返回脏数据或产生部分副作用；
- 无限循环、重试风暴和成本失控；
- 状态丢失、重复执行或跨用户记忆污染；
- 模型、Prompt、Embedding 或知识库版本变更导致回归；
- 外部依赖不可用时没有降级与人工兜底。

## 框架与协议

LangChain、LangGraph、LlamaIndex、AutoGen、Agents SDK、MCP 等只在用户实际使用或 JD 明确要求时追问。重点是框架解决了什么编排或集成问题、引入了什么约束、关键版本和替代方案；不考察无关 API 记忆。

## 挖透标准

候选人应能解释真实请求路径、模型与工具边界、状态和停止条件、一个失败恢复、安全控制、可重复评测以及个人贡献。只能展示 Demo 或罗列框架名时不能标为可应对生产级追问。
