# Python、Java 与 MySQL 项目知识

## 使用边界

只有当前项目实际使用某语言或数据库，或目标 JD 明确要求且用户选择补漏时，才读取对应部分。问题考察项目中的工程判断和基础知识，不要求现场编写代码、完整 SQL 或运行程序。

先问“这项技术在项目中承担什么职责”，再选择知识点。用户只是用 Pandas Notebook 做分析时，不按后端服务深度追问 Python 并发；用户没有使用 Java 时，不因职位列表出现 Java 就假设项目由 Java 实现。

## Python

### 语言与数据结构

- `list`、`tuple`、`set`、`dict` 的语义、查找需求、顺序、去重和可变性；
- 可变默认参数、浅拷贝与深拷贝、对象引用带来的真实 Bug；
- 迭代器、生成器和惰性计算如何降低大数据处理的峰值内存；
- 推导式、向量化与普通循环的可读性和性能取舍。

只有用户项目出现相应代码或性能问题时深入复杂度，不做孤立语法问答。

### 数据处理

- Pandas/NumPy 的数据类型、缺失值、索引、Join、GroupBy 和内存；
- 数据量变大后是否采用分块、列式存储、向量化、数据库下推或分布式方案；
- 随机性、环境、数据版本和 Pipeline 如何保证可复现；
- Notebook 原型如何转为可测试、可维护的模块。

### 异常与资源

- 捕获的是可恢复异常还是过宽的 `Exception`；
- 是否保留错误上下文、记录必要信息并避免吞错；
- 文件、网络和数据库连接如何可靠关闭；
- 重试是否只针对瞬时错误，是否有停止条件和幂等保证。

### 并发与性能

先区分 IO 密集和 CPU 密集，再问线程、进程、`asyncio`、批处理或向量化的选择。确认事件循环、协作式调度、阻塞调用、取消、超时和共享状态。不要把“异步”自动等同于更快。

### 工程化

- 虚拟环境、依赖锁定、Python 和库版本；
- 包结构、配置、日志、类型标注和接口边界；
- 单元测试、数据测试、集成测试和可复现入口；
- 密钥、路径和环境变量是否与代码分离。

## Java

### 对象与集合

- 接口与实现的选择，`List`、`Set`、`Map` 在项目中的用途；
- `equals` 与 `hashCode` 一致性对集合行为的影响；
- 泛型、不可变对象、空值和边界条件；
- 集合并发修改、排序和大数据量下的复杂度。

### 异常与资源

- Checked 与 Unchecked 异常如何映射业务错误和编程错误；
- 异常是否被吞掉、重复包装或泄漏内部信息；
- `try-with-resources`、连接池和资源释放；
- 分层服务如何传递错误并返回稳定接口。

### 并发

- 线程安全、竞态、可见性、原子性和锁粒度；
- `synchronized`、Lock、原子类、并发集合和线程池的实际选择；
- 任务取消、超时、队列积压、拒绝策略和死锁；
- 并行处理是否经过测量，是否因共享状态或数据量过小反而变慢。

### JVM 与服务工程

- 堆、栈、对象生命周期和垃圾回收只追问到项目问题所需深度；
- 内存泄漏、频繁 GC、线程过多或延迟抖动如何观察；
- 接口设计、序列化、幂等、重试、日志和监控；
- 构建工具、依赖版本、测试和部署环境。

用户只做算法原型而未构建 Java 服务时，不把 JVM 调优作为核心项目追问。

## MySQL

### 数据建模

- 表的业务实体、主键、粒度、关系和生命周期；
- 字段类型、NULL、默认值、约束和时间处理；
- 规范化、反规范化和冗余字段的读取性能与一致性取舍；
- 历史数据、软删除、审计和数据权限。

### 索引与查询

- 索引服务哪个查询模式，选择性和写入成本如何；
- 单列、联合、唯一、覆盖索引和最左匹配的项目含义；
- `EXPLAIN` 中访问方式、候选与实际索引、扫描行数、排序或临时表信号；
- Join 顺序、过滤、聚合、分页、批量查询和 N+1 问题；
- 优化是否由真实慢查询、执行计划和前后测量支持。

不能只问“建了索引为什么更快”。应联系 WHERE、JOIN、ORDER BY、数据分布、返回行数和写入负担。

### 事务与并发

- 一个业务事务需要保持什么不变量；
- 原子性、一致性、隔离性和持久性如何在项目中体现；
- 当前 MySQL 与存储引擎版本、隔离级别及选择依据；
- 脏读、不可重复读、幻读、快照读和锁定读在具体流程中的风险；
- 行锁、范围锁、死锁、锁等待和重试；
- 应用层重试是否可能重复扣款、重复写入或破坏幂等。

默认隔离级别、锁行为和优化器细节可能随版本与存储引擎变化，精确纠错前必须查对应官方文档。

### 数据质量与运维

- 数据导入、迁移、回填和 Schema 变更如何校验；
- 连接池、超时、慢查询、容量和备份恢复；
- 分库分表、读写分离或缓存只在用户真实使用时追问；
- 分析查询与在线事务是否相互影响。

## 跨技术追问

项目同时使用 Python/Java 和 MySQL 时，优先追边界问题：参数化查询、连接与事务生命周期、批量写入、序列化、时区、NULL、重试、幂等和监控。不要把三个独立知识列表连续轰炸给用户。

## 纠错和提示

用户概念错误时，指出它会在其项目中导致的具体后果，再让用户重答。只有在第二次仍卡住时提供思考方向或最小解释。模拟面试结束前不直接公布完整答案。

## 挖透标准

候选人至少能说明技术在项目中的职责、一个关键实现选择、一个错误或性能风险、验证或监控方式，以及可替代方案。只会语法或背概念不能证明工程能力。
