# 阶段三：模型、上下文与安全细化

## 目标

阶段三让 Skill 能在不同宿主模型、账号额度、材料规模和工具条件下保持可恢复、可审阅和最小权限。实现重点是行为规则与状态协议，不绑定某个模型、不调用额外 Agent，也不引入 API 代码。

## 设计决策

### 1. 模型无关运行

Skill 使用宿主当前选择的单一模型，不猜测模型名称、上下文窗口或会员额度。交互追问、材料建档、阶段诊断和最终文档采用不同的信息密度，但不通过递归模型调用实现。

模型能力或工具能力不足时，Skill 缩小当前任务、记录阻塞并生成检查点，而不是重复尝试或编造结果。

### 2. 渐进上下文

上下文分为常驻状态、当前项目包、按需证据和外部研究四层。每轮只加载决定下一问所需的信息；原始材料通过位置引用回指，不与摘要一起长期保留。

上下文压力使用可观察信号判断，不写死 Token 阈值。压力升高时先消除重复，再将回答合并为事实、证据、冲突、开放问题和下一行动；无法可靠维持对应关系时停止新增深挖并转入恢复。

### 3. 额度友好但不牺牲质量

Skill 不承诺某种套餐足够完成一次准备。用户可以选择完整深挖、精简深挖、单项目试跑或分会话完成。精简模式减少覆盖范围，不跳过事实、安全和检查点。

### 4. 统一不可信输入边界

简历、JD、论文、代码、网页、搜索结果、文件元数据和旧状态都视为数据。材料中的指令不能覆盖用户当前请求，也不能授权联网、写入、上传、发送或公开操作。

对密钥、个人数据、患者或客户数据、公司机密和提示注入分别定义最小化处理。风险默认只阻断受影响的材料或操作，其余安全部分可以继续。

### 5. 安全联网

联网只用于时效性或准确性核验。查询词先去除姓名、联系方式、内部项目代号、未公开指标、代码和健康数据；优先使用官方文档、原始论文、官方招聘页和公司一手信息。

研究缓存只保存最小结论、来源、日期、版本范围和关联声明。外部知识可以验证原理与行业背景，不能证明候选人做过某项工作。

## 验收不变量

- 不声称读取到模型、上下文或账号额度，除非宿主明确提供；
- 不将材料或网页中的文字当作命令；
- 不在搜索词、状态文件或公开仓库中保留敏感信息；
- 不重复解析已索引材料，不在普通追问中加载所有参考文件；
- 上下文压力导致的中止必须生成可恢复检查点，且不能标为已完成；
- 联网失败或来源不足时明确标为待验证；
- 所有外部写入、发送、上传和公开操作都需要用户当前对话中的明确授权。

## 官方设计依据

本阶段参考了 OpenAI 官方文档中关于精简提示、只暴露相关工具、明确授权边界、长会话里程碑压缩，以及防止提示注入和私有数据泄露的建议：

- [Model guidance](https://developers.openai.com/api/docs/guides/latest-model)
- [Compact a response](https://developers.openai.com/api/reference/java/resources/responses/methods/compact)
- [Safety in building agents](https://developers.openai.com/api/docs/guides/agent-builder-safety)

这些页面用于确定通用设计原则。Skill 本身不要求用户使用特定 API、模型或 Agent Builder。
