# 阶段二：动态追问引擎设计

## 目标

将 V1.1 的提问原则转化为可执行决策循环，使 Skill 根据用户上一轮回答中的证据缺口生成下一问，而不是顺序播放固定题库。

## 组成

- `references/question-engine.md`：通用抽取、检查、决策和提问循环；
- `references/business-deep-dive.md`：业务证据链与完成标准；
- `references/technical-defense.md`：技术证据链、关键词触发和编程知识边界；
- `references/behavioral-and-mock.md`：行为故事和真实模拟面试规则；
- `evals/phase-2-scenarios.md`：阶段二行为验收场景。

## 设计决策

### 证据缺口驱动

下一问由当前声明缺少什么决定，而不是由题库中的下一题决定。题目模板只提供方向，不能覆盖用户刚刚提供的上下文。

### 非数字优先级

内部使用安全、矛盾、未回答、岗位相关风险、盲区和换气的顺序决策，不为用户显示分数，也避免为了计算分数引入虚假的精确度。

### 单动作单问题

每轮只选择一个决策动作并提出一个主问题。这样用户能够判断自己具体回答了什么，也便于状态记录和跨会话恢复。

### 提示可逆

提示从重述到示范逐级升级；用户一旦恢复回答，立即回到正常追问。示范只能使用已确认事实。

### 模式按需加载

`SKILL.md` 常驻通用约束；进入特定模式时才读取该模式参考文件，避免把所有问题维度同时放入上下文。

## 阶段边界

本阶段实现决策与提问规则，不建设大规模行业术语库，不执行自动联网采集，也不实现数字评分。知识资源、安全细化、输出模板和自动化评测属于后续阶段。
