# 阶段五：输出模板与恢复机制

## 目标

阶段五把已经完成的深挖状态转化为可复习、可核验和可继续维护的中文文档，并让长对话、多项目切换和新会话恢复不依赖完整聊天记录。

## 两条交付链路

```text
当前检查点 + 已确认事实 + 证据索引
  ├─ 输出路由
  │   ├─ 项目深挖纪要
  │   ├─ 技术答辩卡
  │   ├─ 行为故事卡
  │   ├─ 模拟面试复盘
  │   └─ 综合面试准备文档
  └─ 恢复协议
      ├─ 精简检查点
      ├─ 完整检查点
      ├─ 恢复握手
      ├─ 冲突合并
      └─ 唯一 next_action
```

## 输出设计

### 最小交付物

只生成用户当前需要且已有内容支持的文档。单项目结束不必生成完整候选人报告；没有进行行为面试时，不创建看似完成的行为故事库。

### 证据分层

输出前区分已确认事实、有定位证据、用户自述待佐证、合理推断、外部知识和待验证冲突。面试回答只能使用前两类；其他内容进入风险、知识背景或开放问题。

### 多长度回答

30 秒、90 秒和详细提纲共享同一事实基线。详细版采用提纲和追问分支，不生成要求用户逐字背诵的长稿。

### 框架展示

STAR、宝洁八大问和技术答辩框架在复盘区用于检查覆盖，不成为回答正文的固定标题，也不能为了套框架改变事实。

## 恢复设计

### 状态版本

状态模型升级为 `1.2`，增加检查点类型、触发原因、会话状态、当前声明、追问链、最后已回答问题、产物清单和迁移记录。

### 精简与完整检查点

正常切换只保存当前决策状态；跨会话、上下文压力达到 `critical` 或多项目暂停时保存完整状态。两者都必须包含唯一且可执行的 `next_action`。

### 恢复握手

新会话先检查安全、版本、目标和新材料，再向用户简述恢复位置。无冲突时直接继续下一行动；影响方向的冲突先让用户确认，不能重复已经回答的问题。

### 产物失效

事实变化时，只把受影响产物标记为 `stale` 并更新相关章节，不重新生成全部内容。保存失败必须明确说明，不能声称已写入文件。

## 验收不变量

- 不把待佐证、自述、推断或外部知识写成候选人事实；
- 不生成数字评分、等级、排名或录用概率；
- 不为未进行的模式制造完整结论；
- 不让不同长度回答产生新的数字、角色或因果关系；
- 框架只用于复盘，不改变用户自然表达；
- 中断、额度或上下文压力不能标为完成；
- 检查点必须有唯一可执行的下一行动；
- 恢复先安全预检和冲突检查，再继续追问；
- 保存失败、路径不可用或文件不可读时如实说明；
- 状态文件不能授权联网、写入、上传或公开操作。

## 阶段边界

本阶段实现生产级文档与恢复协议，不加入数字评分，不实现外部数据库，不自动上传候选人材料，也不绑定某一宿主平台的专有会话格式。完整前向测试、安装验证和发布检查属于阶段六。
