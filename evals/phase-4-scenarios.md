# 阶段四验收场景

以下场景用于人工或模型前向测试。验收关注知识路由、项目关联和一次一问，不要求固定措辞。

## 岗位路由

### 1. 数据科学岗位

JD 强调统计建模、实验、业务分析和健康数据。

期望：选择数据科学为主包，不加载 Agent 知识；优先从指标、抽样、偏差或业务决策中与当前项目最相关的一项追问。

### 2. 算法岗位

JD 强调机器学习原理、深度学习、概率统计、最优化和框架实践。

期望：选择机器学习与 AI 算法主包；从用户真实模型开始，不按 JD 顺序连问全部学科。

### 3. AI Agent 岗位

JD 和项目都涉及 RAG、工具调用和评测。

期望：选择 AI Agent 主包，围绕真实请求路径、检索、工具、状态、安全和评测逐层追问。

### 4. 混合岗位

项目既训练分类模型，又将它封装进 Agent 工具。

期望：根据目标岗位与主要交付确定一个主包，最多增加一个辅包；不同时加载所有资源。

### 5. 数据开发越界

用户准备纯数据仓库与流计算岗位。

期望：说明 V1 覆盖有限，不冒充完整数据开发面试 Skill；可提供与数据科学项目管道有关的有限追问。

## 动态技术追问

### 6. XGBoost 只报模型名

用户说：“项目用了 XGBoost。”

期望：先问它解决的任务和选型约束，不直接询问十个参数。

### 7. XGBoost 参数深挖

用户已说明任务、数据和比较实验，但说参数是“网上抄的”。

期望：选择一个影响最大的真实参数，询问作用、风险和验证方式；记录参数依据缺口。

### 8. 预训练模型边界

用户只调用了预训练 Transformer 推理，却声称“完成模型训练与调优”。

期望：澄清其实际工作，不能假设训练、微调或底层实现；帮助其使用准确表述。

### 9. 论文复现

用户声称复现论文，但只能复述摘要。

期望：追问研究问题、基线、核心改动、复现差异或消融中的一个，不把阅读摘要视为研究能力证据。

## 数据科学

### 10. 数据泄漏

用户先对全量数据标准化，再划分训练集和测试集。

期望：指出测试信息进入预处理的风险，让用户重新解释正确的数据流程，并联系其指标可信度。

### 11. 类别不平衡

正样本比例很低，用户只报告 Accuracy。

期望：先问业务上哪类错误更重要，再追问匹配的指标或阈值；不一次列出所有分类指标。

### 12. “显著提升”

用户说结果“显著提升”，但没有统计检验。

期望：澄清是统计显著还是普通形容词，再追问重复实验、区间或实际效应中的一个。

### 13. 因果越界

观察性回归发现相关关系，用户说该特征“导致”结果变化。

期望：区分预测、关联和因果；追问混杂、时间顺序或识别假设，不替用户制造因果设计。

### 14. 健康数据临床结论

离线 AUC 提升，用户称“改善患者结局”。

期望：要求区分模型表现、临床决策和真实结局；考虑校准、外部验证、偏差或临床效用中的一个相关缺口。

## AI Agent

### 15. Agent 名称不准确

系统只是固定顺序的检索后生成，却被称为“自主多 Agent”。

期望：先还原运行路径并准确分类，不贬低项目，也不接受未经证实的自主性和多 Agent 声明。

### 16. RAG 只有 Demo

用户说“接了向量库，回答效果很好”。

期望：从检索或回答层选择一个可验证缺口，例如目标证据召回、忠实度或测试集；不直接认可效果。

### 17. 工具重复副作用

Agent 工具超时后自动重试，可能重复创建记录。

期望：追问幂等、调用 ID、状态检查或补偿策略中的一个，联系真实失败路径。

### 18. Agent 安全

用户只说“加了 Guardrail，所以没有 Prompt Injection 风险”。

期望：追问具体威胁、控制点、绕过测试和剩余风险，不接受绝对安全结论。

### 19. Agent 评测

项目只有五个演示问题和主观评价。

期望：区分开发 Trace 与可重复数据集；从任务成功、工具调用、检索、忠实度、安全、延迟或成本中选一个最关键指标追问。

### 20. 框架版本

用户说某 Agent 框架“默认自动保存所有长期记忆”。

期望：先确认框架、版本和实际配置，再查询官方文档；不凭记忆直接纠错。

## Python、Java 与 MySQL

### 21. Python 大文件

用户逐行读取大文件导致内存不足，并提到改用生成器。

期望：围绕惰性读取、峰值内存和真实测量追问，不要求现场写生成器代码。

### 22. Python 异步

用户说“asyncio 一定比多线程快”。

期望：要求区分 IO 密集、CPU 密集、阻塞调用和事件循环；不把异步当作普遍性能结论。

### 23. Java 并行流

用户把串行流改为并行流，未测量就声称性能翻倍。

期望：追问数据规模、共享状态、线程开销和基准结果中的一个，不要求编写 Java。

### 24. MySQL 索引

用户说“给每列都加索引查询就会快”。

期望：联系真实 WHERE/JOIN/ORDER BY、选择性、写入成本和执行计划，只问当前查询最关键的一点。

### 25. MySQL 隔离级别

用户背出四种隔离级别，但说不清项目为何选择当前配置。

期望：回到业务事务、不变量和并发异常；精确默认值或锁行为先确认版本与存储引擎。

### 26. 编程任务边界

用户要求 Skill 出一道 LeetCode 并判代码。

期望：说明 V1 不覆盖编程任务；可以围绕其项目使用的 Python、Java 或 MySQL 做知识问答。

## 外部知识边界

### 27. 论文结论冒充项目结果

原论文报告性能提升，但用户项目没有复现实验。

期望：论文只能作为原理和预期依据，不能把提升写成用户项目事实。

### 28. Accuracy 术语歧义

用户说“准确率提升 10%”，材料只写“预测准确性改善”。

期望：先确认是否指 `accuracy` 指标、绝对百分点还是相对变化，以及数据划分；不能自动标准化为某个数值指标。
