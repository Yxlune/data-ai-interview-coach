# 阶段二行为验收场景

以下场景用于人工或模型前向测试。验收关注行为不变量，不要求输出固定措辞。

## 场景 1：模糊效率

用户说：“这个项目提升了运营效率。”

期望：只追问一个最关键证据缺口，例如效率的具体口径；不能一次询问指标、基线、测量、归因和成本。

## 场景 2：团队贡献

用户说：“我们完成了模型开发和上线，我主要参与了建模。”

期望：澄清用户亲自负责的建模环节或关键判断；不能把上线成果直接归给用户。

## 场景 3：XGBoost 选型

用户说：“我们选择 XGBoost，因为它效果最好。”

期望：沿当前线索确认比较依据或候选方案，只问一个主问题；不立即罗列全部 XGBoost 参数。

## 场景 4：XGBoost 参数

用户已说明通过交叉验证选择 XGBoost，但说不清 `max_depth`。

期望：围绕该参数在项目中的作用和过拟合关系追问；用户卡壳后按提示阶梯提供方向。

## 场景 5：技术指标不等于业务价值

用户说：“AUC 提升了 0.03，所以项目业务价值很高。”

期望：识别技术指标到业务价值之间缺少联系，追问一个业务口径；不能直接认可因果关系。

## 场景 6：用户连续不知道

用户连续两次说“不知道为什么选择这个指标”。

期望：不重复原问题，升级到缺失维度或 2–3 个思考方向；不直接生成带虚构事实的答案。

## 场景 7：同一线索过长

同一贡献线已经连续追问四轮，并完成动作和结果确认。

期望：进入复盘或给出少量可选发散方向，不继续同义追问。

## 场景 8：健康数据科学

用户声称模型性能提升可以改善患者结局，但只有离线数据实验。

期望：区分离线模型表现和临床效果，确认验证边界，并考虑隐私、偏差或标签质量中的相关风险。

## 场景 9：AI Agent 演示

用户说：“Agent 在 Demo 中可以自动调用工具，所以能够稳定用于生产。”

期望：识别演示到生产可靠性的证据缺口，围绕评测、权限、失败恢复或人工介入选择一个问题。

## 场景 10：Java 与岗位知识

岗位要求 Java，但用户项目仅使用 Python。

期望：不假装 Java 属于项目；只有用户选择岗位知识补漏时，才单独考察 Java 知识。

## 场景 11：行为故事

用户用大量背景描述一次团队冲突，但没有说明自己的动作。

期望：把问题拉回用户采取的一个具体动作；不立即要求重讲完整 STAR。

## 场景 12：模拟面试答错

用户在模拟面试中错误解释 Boosting。

期望：记录技术缺口并保持面试节奏，不立即长篇教学；面试结束后统一纠错。

## 场景 13：材料冲突

简历写“独立完成”，用户回答说模型由导师提供。

期望：优先展示冲突并请求确认，不能继续基于“独立完成”追问或替用户圆谎。

## 场景 14：结束判断

项目已说明原因、个人贡献、验证结果、技术局限和复盘。

期望：关闭当前线索或创建检查点，不为覆盖题库继续提问。
